# Сценарии, меню и тексты

Документ фиксирует пользовательские экраны, точные тексты, клавиатуры и правила навигации.
Тексты — черновик для согласования; после утверждения они переносятся в `app/texts.py`
без изменения смысла.

## 1. Принципы

- Один экран — одно сообщение с клавиатурой.
- Навигация без состояния: каждое действие закодировано в `payload` кнопки.
- Возврат всегда явный: «К списку услуг», «В главное меню». Кнопки «Назад» без указания
 места возврата не используем.
- Старые кнопки продолжают работать, если действие и ID услуги всё ещё существуют.
- Бот не спорит с человеком: после подтверждения перехода к менеджеру он замолкает.
- В сообщениях нет Markdown: ВКонтакте показывает обычный текст. Используем переносы строк,
  «•» и «—».
- Никаких обещаний лечения и медицинских рекомендаций.

## 2. Карта экранов

```text
Старт / «Начать»
      │
      ▼
Главное меню ──────────────► Прайс-лист
      │                          │
      ├──► Список услуг ◄────────┘
      │         │
      │         ▼
      │    Карточка услуги
      │         │
      │         ├──► Список услуг
      │         └──► Главное меню
      │
      └──► Связаться с менеджером
                   │
                   ▼
            «Я написал менеджеру»
                   │
                   ▼
              Тихий режим
                   │
                   ▼
             «В главное меню»
```

## 3. Действия и payload

`[РЕШЕНИЕ]` Схема: `{"v": 1, "a": "<действие>", "id": "<услуга>"}`. Поле `id` обязательно
только для `svc`.

| Действие | Payload | Результат |
|---|---|---|
| `menu` | `{"v":1,"a":"menu"}` | главное меню |
| `list` | `{"v":1,"a":"list"}` | список услуг |
| `price` | `{"v":1,"a":"price"}` | прайс-лист |
| `svc` | `{"v":1,"a":"svc","id":"vision_exam_glasses"}` | карточка услуги |
| `mgr` | `{"v":1,"a":"mgr"}` | экран связи с менеджером |
| `mgr_ack` | `{"v":1,"a":"mgr_ack"}` | тихий режим |
| неизвестно | любой другой payload | сообщение об устаревшей кнопке + меню |

`[РЕШЕНИЕ]` Кнопка ВКонтакте «Начать» присылает payload `{"command":"start"}`. Обрабатываем его
как старт и показываем приветствие.

`[РЕШЕНИЕ]` Если payload отсутствует, но текст совпадает с явной командой («начать», «меню»,
«услуги», «прайс», «менеджер»), выполняем соответствующее действие. Это удобно для пользователей,
которые пишут текстом.

`[ПРЕДПОЛОЖЕНИЕ]` Библиотека корректно разбирает payload; при повреждённом JSON обработчик
считает действие неизвестным и не падает. Проверяется тестом.

## 4. Клавиатуры

### 4.1. Главное меню

```text
[ Услуги ]  [ Прайс-лист ]
[ Связаться с менеджером ]
```

- `one_time=False`, `inline=False`;
- «Услуги» — primary, «Прайс-лист» — secondary, «Связаться с менеджером» — positive.

### 4.2. Список услуг

```text
[ Проверка зрения для очков ] [ Расширенная проверка ] [ Подбор контактных линз ]
[ Сборка очков ]              [ Лазерная сварка ]      [ Замена носоупоров ]
[ Замена винтов ]             [ Переустановка линз ]   [ Регулировка оправы ]
[ Ультразвуковая чистка ]
[ К списку услуг ]            [ В главное меню ]
```

`[РЕШЕНИЕ]` 10 услуг в четырёх рядах плюс ряд навигации. Подписи короче 40 символов,
payload — меньше 255 символов.

### 4.3. Карточка услуги

```text
[ К списку услуг ] [ В главное меню ]
[ Связаться с менеджером ]
```

### 4.4. Прайс-лист

```text
[ К услугам ] [ В главное меню ]
[ Связаться с менеджером ]
```

### 4.5. Связь с менеджером

```text
[ Написать менеджеру ]   ← OpenLink на MANAGER_CONTACT_URL
[ Я написал менеджеру ] [ В главное меню ]
```

`[РЕШЕНИЕ]` Кнопка «Написать менеджеру» — `OpenLink`: она сразу открывает диалог сообщества.
Кнопка «Я написал менеджеру» — обычная текстовая кнопка с payload `mgr_ack`.

### 4.6. Тихий режим

```text
[ В главное меню ]
```

## 5. Тексты

### 5.1. Приветствие и главное меню

```text
Здравствуйте! Это бот салонов оптики «Ясные очи».

Здесь можно посмотреть услуги и ориентировочные цены, а также связаться с менеджером.

Выберите раздел:
```

Повторное открытие меню:

```text
Главное меню. Выберите раздел:
```

### 5.2. Список услуг

```text
Услуги салонов «Ясные очи»

Выберите услугу, чтобы посмотреть описание, состав и цену. Цены ориентировочные — уточняйте у менеджера.
```

### 5.3. Карточка услуги

Шаблон:

```text
{name}

{price} {unit}

{full}

Что входит:
• {include_1}
• {include_2}
...

Важно:
• {caveat_1}
• {caveat_2}
...

Цены ориентировочные, не являются публичной офертой.
```

Пример для `vision_exam_glasses`:

```text
Проверка зрения для рецепта на очки

2 500 ₽ за приём

Приём в кабинете: специалист уточняет жалобы и условия работы, проверяет остроту зрения и рефракцию, проводит уточняющие тесты. По результатам подбираются монофокальные очки для дали, близи или постоянного ношения и оформляется рецепт. Если выявляются изменения, которые требуют врачебной оценки, специалист может порекомендовать отдельную консультацию офтальмолога.

Что входит:
• сбор жалоб и анамнеза;
• авторефрактометрия;
• визометрия — проверка остроты зрения;
• уточняющие тесты и подбор монофокальных линз;
• рецепт на очки.

Важно:
• в стоимость не входят очки, линзы и оправа;
• бесплатная проверка при заказе очков в день приёма — проектная гипотеза, требует подтверждения;
• приём не заменяет медицинское обследование и не является лечением.

Цены ориентировочные, не являются публичной офертой.
```

### 5.4. Прайс-лист

```text
Прайс-лист

Цены ориентировочные, Москва и Московская область, проверено 10.11.2026. Не являются публичной офертой.

• Проверка зрения для рецепта на очки — 2 500 ₽ за приём
• Расширенная проверка зрения — 3 000 ₽ за приём
• Подбор контактных линз — 2 500 ₽ за подбор
• Сборка очков — от 1 300 ₽ за комплект
• Лазерная сварка оправы — от 1 500 ₽ за шов
• Замена носоупоров — от 300 ₽ за пару
• Замена винтов и крепежа — от 300 ₽ за единицу
• Переустановка линз в новую оправу — 700 ₽ за пару
• Регулировка и выправка оправы — от 500 ₽ за приём
• Ультразвуковая чистка очков — от 300 ₽ за пару

Полные описания — в разделе «Услуги». Стоимость материалов и изделий уточняйте у менеджера.
```

### 5.5. Связь с менеджером

```text
Связь с менеджером

Напишите менеджеру в диалоге сообщества:
{MANAGER_CONTACT_URL}

Отвечает человек, а не бот. Если менеджер сейчас недоступен, сообщение останется в диалоге, и ответ придёт позже.

После того как напишете, нажмите «Я написал менеджеру». Бот перестанет отвечать на обычные сообщения, чтобы не мешать разговору.
```

### 5.6. Подтверждение тихого режима

```text
Хорошо. Я не буду отвечать на обычные сообщения, пока вы общаетесь с менеджером.

Вернуться в меню можно кнопкой «В главное меню». Через {TTL} часов бот снова начнёт отвечать автоматически.
```

`{TTL}` подставляется из `MANAGER_MODE_TTL_HOURS`, по умолчанию 12.

### 5.7. Выход из тихого режима

```text
Бот снова на связи.

Главное меню. Выберите раздел:
```

### 5.8. Неизвестный ввод

```text
Не понял сообщение.

Пользуйтесь кнопками ниже:
• «Услуги» — список услуг и карточек;
• «Прайс-лист» — все цены;
• «Связаться с менеджером» — переписка с человеком.
```

### 5.9. Устаревшая кнопка

```text
Эта кнопка устарела: такого раздела больше нет.

Открываю актуальное меню.
```

### 5.10. Услуга не найдена

```text
Услуга не найдена: возможно, она больше не публикуется.

Открываю список актуальных услуг.
```

### 5.11. Общая ошибка действия

Используется только если сообщение ещё можно отправить:

```text
Не получилось выполнить действие. Попробуйте ещё раз или вернитесь в главное меню.
```

## 6. Сценарии

### 6.1. Первый запуск

1. Пользователь открывает диалог и нажимает «Начать» или пишет «привет».
2. Бот отвечает приветствием и показывает главное меню.
3. Никакие данные о пользователе не сохраняются.

`[РЕШЕНИЕ]` Первый и повторный запуск выглядят одинаково. Отдельный флаг «уже видел бота»
не нужен: он усложняет хранение и не улучшает сценарий.

### 6.2. Повторное обращение

1. Пользователь снова пишет боту.
2. Если тихого режима нет — бот показывает главное меню.
3. Прошлый экран не восстанавливается: навигация stateless.

### 6.3. Просмотр услуги

1. «Услуги» → список.
2. Нажатие кнопки услуги → карточка.
3. «К списку услуг» → список.
4. «В главное меню» → меню.

### 6.4. Прайс-лист

1. «Прайс-лист» → сообщение со всеми ценами.
2. «К услугам» → список.
3. «В главное меню» → меню.

`[РЕШЕНИЕ]` Прайс-лист и карточки используют один каталог; расхождение цены — дефект.

### 6.5. Неизвестный ввод

1. Пользователь пишет «сколько стоит» или случайный текст.
2. Бот отвечает текстом 5.8 и показывает главное меню.
3. Бот не пытается угадать услугу и не даёт медицинских советов.

### 6.6. Устаревшая кнопка

| Ситуация | Поведение |
|---|---|
| Кнопка услуги, услуга ещё есть | открыть актуальную карточку |
| Кнопка услуги, услуга удалена | текст 5.10 + список услуг |
| Неизвестное действие | текст 5.9 + главное меню |
| Payload без поля `v` | считать устаревшим, текст 5.9 + меню |
| Повреждённый payload | считать устаревшим, не падать |

### 6.7. Связь с менеджером

1. Пользователь нажимает «Связаться с менеджером».
2. Бот показывает экран 5.5 и кнопку-ссылку.
3. Пользователь переходит в диалог сообщества и пишет менеджеру.
4. Пользователь нажимает «Я написал менеджеру».
5. Бот включает тихий режим и отвечает текстом 5.6.
6. Все обычные сообщения пользователя игнорируются до выхода или истечения TTL.
7. «В главное меню» выключает тихий режим и показывает меню.

### 6.8. Менеджер вступил в переписку

`[ФАКТ]` Бот обрабатывает только входящие сообщения пользователей. Исходящие сообщения
менеджера не запускают обработчики.

`[РЕШЕНИЕ]` Если пользователь нажал «Я написал менеджеру», бот молчит и не мешает. Если
пользователь этого не сделал, автоматического определения «менеджер уже ответил» нет.
В этом случае бот может ответить на следующее сообщение пользователя — это ограничение
принятого механизма, а не скрытая автоматическая передача.

`[ПРЕДПОЛОЖЕНИЕ]` В будущем можно включить событие `message_reply` и автоматически входить
в тихий режим при ответе менеджера. Это требует отдельной проверки и не входит в MVP.

### 6.9. Перезапуск

1. Процесс останавливается и запускается снова.
2. Навигация не ломается: состояние экрана не хранится.
3. Тихий режим восстанавливается из `runtime/state.json`, если TTL не истёк.
4. Если файл повреждён, бот работает без тихого режима и пишет предупреждение в лог.

## 7. Ограничения механизма менеджера

- Бот не передаёт диалог автоматически и не создаёт заявку.
- Бот не уведомляет менеджера о новом обращении.
- Бот не знает, ответил ли менеджер.
- Бот не может отличить менеджера от пользователя без отдельного механизма.
- Тихий режим — это соглашение: пользователь подтверждает, что написал менеджеру.
- TTL защищает от «вечного молчания», если пользователь забыл выйти.
- В тихом режиме отвечает только кнопка «В главное меню»; остальные кнопки и текст игнорируются.

`[ВОПРОС]` Если владелец хочет, чтобы бот автоматически замолкал при ответе менеджера, нужен
отдельный механизм и проверка события `message_reply`. Это меняет объём MVP.

## 8. Форматирование и лимиты

- Одно сообщение — до 4096 символов; фактический лимит проверить при реализации.
- Карточка и прайс-лист укладываются в одно сообщение.
- Списки — через «•», без вложенных списков.
- Ссылка на менеджера выводится отдельной строкой, чтобы клиент сделал её кликабельной.
- Эмодзи не используем: они удешевляют тон и могут по-разному отображаться.
- Markdown не используем: ВКонтакте не рендерит его в сообщениях.

## 9. Тон и запреты

Можно: «уточняйте у менеджера», «специалист может порекомендовать», «решение принимает мастер».

Нельзя:

- «мы вылечим», «гарантируем зрение», «лучшая клиника»;
- «бесплатно» без подтверждения;
- «точная цена» без оговорки;
- медицинские советы и диагнозы;
- обещание результата;
- упоминание лицензии и оборудования как факта без подтверждения.
