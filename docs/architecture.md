# Архитектура приложения

**Тип:** один синхронный процесс Python, один экземпляр бота.
**Транспорт:** LongPoll API ВКонтакте.
**Хранилище:** JSON-каталог + один файл состояния.
**Дата:** 11.11.2026 · **Этап:** MVP реализован, LongPoll подключается, выполнен короткий smoke-запуск.

## 1. Принципы

`[РЕШЕНИЕ]` Архитектура намеренно минимальна:

1. **Один процесс.** Нет веб-сервера, брокера, воркеров и планировщика.
2. **Один источник контента.** Все тексты услуг, цены и оговорки — в `catalog/services.json`.
3. **Stateless-навигация.** Текущий экран не хранится; действие закодировано в `payload`.
4. **Одно сохраняемое состояние.** «Тихий режим» менеджера в `runtime/state.json`.
5. **Отказ от базы данных.** Данные малы, конкурентной записи нет, нужен просмотр и правка
   без инструментов.
6. **Идемпотентность.** Повторное нажатие кнопки или повтор события не создаёт побочных эффектов.

## 2. Компоненты

```text
┌──────────────────────────── ВКонтакте ────────────────────────────┐
│  Пользователь → сообщение / текстовая кнопка с payload            │
└───────────────────────────────┬───────────────────────────────────┘
                                │ LongPoll (исходящий запрос бота)
                                ▼
┌────────────────────────────── app ────────────────────────────────┐
│  __main__.py        точка входа: настройка логов, сборка, bot.run()│
│  config.py          чтение .env, валидация, параметры запуска      │
│  catalog.py         загрузка и валидация services.json             │
│  texts.py           шаблоны сообщений и форматирование цены        │
│  keyboards.py       сборка клавиатур и payload                     │
│  manager_state.py   тихий режим: чтение/запись/TTL/атомарность     │
│  handlers/          обработчики событий                            │
└───────┬───────────────────────────────┬───────────────────────────┘
        │                               │
        ▼                               ▼
 catalog/services.json            runtime/state.json
 (контент, только чтение)         (тихий режим, чтение/запись)
```

`[РЕШЕНИЕ]` VKBottle используется на «высоком» уровне: `Bot`, `BotLabeler`, `Message`,
`Keyboard`. Низкоуровневый `Polling` не нужен — библиотека уже реализует цикл, `ts` и сбои.

## 4. Движение данных

### 4.1. Запуск

```text
python -m app
  → config.load_settings()
      → нет VK_BOT_TOKEN / MANAGER_CONTACT_URL → сообщение об ошибке, exit code 2
  → catalog.load_catalog()
      → файл не найден / невалиден → сообщение об ошибке, exit code 3
  → logging setup
  → manager_state.load()
      → файла нет → пустое состояние
      → файл повреждён → предупреждение в лог, пустое состояние
  → Bot(token=..., labeler=..., skip_old_events=False)
  → bot.run()
```

`[РЕШЕНИЕ]` Ошибки конфигурации обнаруживаются **до** подключения к ВКонтакте: неверный каталог
не должен доходить до пользователей.

### 4.2. Обработка сообщения

```text
message_new
  → проверка quiet mode по peer_id
      → активен и это не payload-кнопка «В главное меню» → молча выйти
      → активен и payload == {"v":1,"a":"menu"} → выключить quiet mode, показать меню
      → активен, но текст «меню»/«привет» → молча выйти
  → разбор payload (get_payload_json)
      → a="menu"  → главное меню
      → a="list"  → список услуг
      → a="price" → прайс-лист
      → a="svc"   → карточка по id
      → a="mgr"   → экран менеджера
      → a="mgr_ack" → включить quiet mode, подтверждение
      → неизвестно → текст «кнопка устарела» + меню
  → payload нет → проверка текстовой команды
      → «начать» / «привет» → приветствие + меню
      → «меню» → меню без приветствия
      → «услуги» → список
      → «прайс» → прайс-лист
      → «менеджер» → экран менеджера
      → иначе → текст «не понял» + меню
  → отправка одного сообщения с клавиатурой
```

`[РЕШЕНИЕ]` Каждый экран — отдельное сообщение. Редактирования предыдущего сообщения нет:
ВКонтакте не даёт надёжно «перерисовать» клавиатуру в истории, а старые кнопки должны
продолжать работать.

### 4.3. Чтение каталога

`[РЕШЕНИЕ]` Каталог загружается один раз при старте в неизменяемую структуру в памяти.
Изменение цен требует перезапуска процесса. Это осознанный компромисс: нет риска прочитать
файл наполовину записанным и нет файловых блокировок на каждый запрос.

`[ПРЕДПОЛОЖЕНИЕ]` Обновление каталога происходит редко (несколько раз в год), поэтому
перезапуск не создаёт заметного простоя.

## 5. Схема каталога

`[РЕШЕНИЕ]` `catalog/services.json` — объект с версией и массивом услуг:

```json
{
  "schema_version": 1,
  "updated_at": "2026-11-10",
  "price_note": "Цены ориентировочные, не являются публичной офертой.",
  "services": [
    {
      "id": "vision_exam_glasses",
      "name": "Проверка зрения для рецепта на очки",
      "button": "Проверка зрения для очков",
      "short": "Определение рефракции и подбор монофокальных очков.",
      "full": "Приём в кабинете: ...",
      "includes": ["сбор жалоб и анамнеза", "авторефрактометрия"],
      "price": 2500,
      "price_type": "fixed",
      "price_unit": "за приём",
      "caveats": ["в стоимость не входят очки, линзы и оправа"],
      "requires_owner_confirmation": true,
      "confirmation_type": "medical",
      "sort_order": 10
    }
  ]
}
```

Поля:

| Поле | Тип | Обязательно | Правило |
|---|---|---|---|
| `id` | string | да | `^[a-z][a-z0-9_]{2,40}$`, уникален, не меняется |
| `name` | string | да | до 120 символов |
| `button` | string | да | до 40 символов, уникален в списке |
| `short` | string | да | одно предложение, до 200 символов |
| `full` | string | да | до 1200 символов, без обещаний лечения |
| `includes` | string[] | да | 1–10 пунктов |
| `price` | integer | да | рубли, `> 0`, без пробелов и знаков |
| `price_type` | string | да | `fixed` или `from` |
| `price_unit` | string | да | «за приём», «за комплект», «за шов», «за пару», «за единицу», «за подбор» |
| `caveats` | string[] | да | 1–10 пунктов |
| `requires_owner_confirmation` | boolean | да | `true` до подтверждения владельцем |
| `confirmation_type` | string | да | `medical` или `workshop` |
| `sort_order` | integer | да | порядок в списке и прайсе, уникален |

`[РЕШЕНИЕ]` Валидация при старте проверяет: JSON разбирается; `schema_version == 1`;
все обязательные поля есть; ID и `sort_order` уникальны; `button` ≤ 40 символов;
`price_type` из допустимых; `price > 0`; списки не пусты. При ошибке процесс завершается
с кодом 3 и сообщением, где указан ID/поле, но без вывода всего файла.

`[РЕШЕНИЕ]` Форматирование цены — одна функция:

```text
fixed → "2 500 ₽"
from  → "от 1 300 ₽"
unit  → отдельной строкой или через пробел: "2 500 ₽ за приём"
```

Прайс-лист и карточка вызывают её с одними и теми же полями, поэтому расхождение невозможно
без изменения кода.

## 6. Почему JSON, а не база данных

| Критерий | JSON-файл | SQLite | PostgreSQL |
|---|---|---|---|
| Объём данных | 10 записей, ~20 КБ | избыточен | избыточен |
| Чтение | один раз при старте | запрос на экран | сеть + запрос |
| Правка контента | текстовый редактор + ревью | нужен SQL/клиент | нужен доступ к серверу |
| Конкурентная запись | нет | есть | есть |
| Резервная копия | копия файла | копия файла | дамп/бэкап |
| Транзакции | не нужны | не нужны | не нужны |
| Новые зависимости | нет | встроен | драйвер + сервер |
| Риск порчи | ловится валидацией | ниже | ниже |

`[РЕШЕНИЕ]` JSON достаточен, потому что:

- каталог только читается во время работы;
- запись — редкая, вручную, вне процесса;
- нет пользовательских данных, которые нужно хранить в таблицах;
- ценность прозрачности и простоты выше ценности транзакций;
- при появлении админки или сотен услуг решение пересматривается.

`[ВОПРОС]` Если владелец захочет менять цены без перезапуска и без доступа к серверу, потребуется
админ-интерфейс и, вероятно, БД. Это выходит за рамки MVP.

## 7. Файл состояния

`[РЕШЕНИЕ]` `runtime/state.json` хранит только тихий режим:

```json
{
  "schema_version": 1,
  "quiet": {
    "123456789": {
      "until": "2026-11-10T22:30:00+03:00",
      "set_at": "2026-11-10T10:30:00+03:00"
    }
  }
}
```

Правила:

- ключ — `peer_id` пользователя;
- `until` — момент истечения TTL;
- запись атомарная: временный файл в том же каталоге + `os.replace`;
- чтение устойчиво к отсутствию, пустому и повреждённому файлу;
- при повреждении — предупреждение в лог и пустое состояние, бот продолжает работу;
- просроченные записи удаляются при чтении и при записи;
- размер файла ограничен: записи старше TTL не накапливаются.

`[ВОПРОС]` По Q-09 владелец запросил журнал обращений на 30 суток. В текущем MVP его нет.
Если журнал хранит только метаданные (`peer_id`, время, действие), нужен отдельный файл
и ротация; если тексты сообщений — меняется политика данных и архитектура. До решения
`runtime/state.json` остаётся единственным сохраняемым состоянием.

`[ПРЕДПОЛОЖЕНИЕ]` Нагрузка низкая, поэтому гонки между задачами обработчиков закрываются
одной `asyncio.Lock` вокруг чтения-изменения-записи. Отдельная БД для этого не нужна.

`[ФАКТ]` Обработчики событий в VKBottle запускаются отдельными задачами, порядок не гарантирован
(`asyncio.create_task` в `run_polling`). Поэтому общий файл нельзя обновлять без блокировки.

## 8. Обработка ошибок

| Ситуация | Поведение | Код/лог |
|---|---|---|
| Нет `VK_BOT_TOKEN` | выход до подключения | exit 2, сообщение без значения |
| Нет `MANAGER_CONTACT_URL` | выход до подключения | exit 2 |
| Некорректный URL менеджера | выход до подключения | exit 2 |
| Каталог не найден | выход | exit 3 |
| Каталог невалиден | выход с указанием поля | exit 3 |
| `state.json` повреждён | предупреждение, пустое состояние | WARNING |
| `VKAPIError` при отправке | лог кода и метода, процесс живёт | ERROR |
| Сеть/LongPoll сбой | повтор внутри библиотеки | WARNING |
| Неизвестный payload | ответ «кнопка устарела» | INFO с `a`/`id` |
| Неизвестный текст | ответ «не понял» | INFO |
| Ошибка в обработчике | лог + попытка ответить общим текстом | ERROR |

`[РЕШЕНИЕ]` Падение обработчика не должно ронять процесс. Регистрируется общий обработчик
исключений и обработчики `VKAPIError`; после ошибки бот продолжает принимать события.

`[РЕШЕНИЕ]` В логах нет: токена, ключа LongPoll, заголовков запросов, текста сообщений
пользователя, содержимого `.env`. Есть: время, уровень, модуль, `peer_id`, действие `a`,
ID услуги, код ошибки.

## 9. Конкурентность и идемпотентность

- Навигация не хранит состояние, поэтому параллельные нажатия не конфликтуют.
- Два быстрых нажатия одной кнопки приведут к двум одинаковым сообщениям — это допустимо.
- Вход в тихий режим идемпотентен: повторная запись обновляет `until`.
- Выход из тихого режима идемпотентен: повторное удаление не ошибка.
- Отправка сообщения не гарантирует доставку; при ошибке API пользователь просто нажмёт снова.

`[ПРЕДПОЛОЖЕНИЕ]` Дедупликация по `event_id` не нужна: побочных эффектов, кроме отправки
сообщения, нет. При появлении оплаты или заявок её придётся добавить.

## 10. Почему нет Docker, веб-сервера и очередей

| Компонент | Почему не нужен |
|---|---|
| Docker | один процесс, нет системных зависимостей; усложняет запуск на одном сервере |
| Веб-сервер | LongPoll инициируется ботом; входящих HTTP-запросов нет |
| Очередь | события уже приходят потоком; критичных операций и ретраев нет |
| Redis | состояние — один маленький файл, конкурентность закрыта блокировкой |
| Планировщик | TTL проверяется лениво при обращении, отдельный cron не нужен |
| Nginx | нет домена, сертификата и входящего трафика |

`[РЕШЕНИЕ]` Если появится второй экземпляр бота или веб-админка, архитектура пересматривается.
Для MVP дополнительные компоненты создают риск без пользы.

## 11. Границы модулей

| Модуль | Знает | Не знает |
|---|---|---|
| `config.py` | `.env`, пути, TTL | ВКонтакте, каталог |
| `catalog.py` | JSON, схема, поиск по ID | сообщения, клавиатуры |
| `navigation.py` | payload, текстовые команды | тексты, API |
| `texts.py` | шаблоны, форматирование цены | API, состояние |
| `keyboards.py` | payload, подписи, раскладка | тексты карточек |
| `screens.py` | действие → текст + клавиатура | ВКонтакте, файлы |
| `manager_state.py` | `runtime/state.json`, TTL | ВКонтакте, каталог |
| `handlers/processor.py` | сценарий одного сообщения, quiet mode | отправка в ВК |
| `handlers/__init__.py` | лейблер, отправка ответа | формат хранения, пути |

`[РЕШЕНИЕ]` Такое разделение позволяет тестировать каталог, цену и quiet mode без сети
и без запуска бота.

## 12. Точка входа и завершение

`[РЕШЕНИЕ]` Запуск: `python -m app`. В `__main__.py`:

- настройка `logging` после чтения конфигурации, но до создания `Bot`;
- `try/except` вокруг `bot.run()`;
- корректная обработка `KeyboardInterrupt`;
- коды выхода: `0` — штатное завершение, `2` — конфигурация, `3` — каталог, `1` — прочее.

`[ФАКТ]` В `vkbottle==4.11.0` метод `run_forever()` помечен `@deprecated`; используется
`bot.run()`. Источник: https://github.com/vkbottle/vkbottle/blob/v4.11.0/vkbottle/framework/base.py
