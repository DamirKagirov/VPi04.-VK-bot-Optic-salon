# LongPoll API: получение событий и настройки сообщества

**Решение:** бот сообщества использует **LongPoll API**, а не Callback API.
**Библиотека:** `vkbottle==4.11.0`, класс `BotPolling`.

## 1. Почему LongPoll

`[РЕШЕНИЕ]` LongPoll выбран потому, что:

- не требует публичного HTTPS-адреса, веб-сервера и сертификата;
- не требует URL, секрета и кода подтверждения Callback;
- подходит для одного процесса на небольшой нагрузке;
- VKBottle берёт на себя получение сервера, цикл опроса и обработку сбоев.

`[ПРЕДПОЛОЖЕНИЕ]` Нагрузка бота — единицы сообщений в минуту. При росте нагрузки или появлении
нескольких экземпляров приложения потребуется отдельное решение (один потребитель событий),
но для MVP это не требуется.

## 2. Как работает LongPoll

`[ФАКТ]` Схема ВКонтакте:

1. Бот запрашивает `groups.getLongPollServer` и получает `server`, `key`, `ts`.
2. Бот делает длинный POST на `server` с параметрами `act=a_check`, `key`, `ts`, `wait`.
3. Если событий нет, сервер держит соединение до `wait` секунд и возвращает пустой ответ.
4. Если события есть, сервер возвращает `updates` и новый `ts`.
5. Следующий запрос использует новый `ts`, чтобы не получать те же события повторно.

`[ФАКТ]` В VKBottle это реализовано в `BotPolling`:

- `wait = min(wait or 25, 90)` — по умолчанию 25 секунд, максимум 90;
- `rps_delay` по умолчанию 0;
- `group_id` определяется через `groups.getById`, если не задан;
- сервер запрашивается через `groups.getLongPollServer`;
- при `skip_old_events=False` `ts` сохраняется в
  `.vkbottle/bot-polling/{group_id}.json` и восстанавливается при старте.

Источник: https://github.com/vkbottle/vkbottle/blob/v4.11.0/vkbottle/polling/bot_polling.py

## 3. Что библиотека делает автоматически

| Действие | Кто выполняет | Комментарий |
|---|---|---|
| Получение `server`, `key`, `ts` | VKBottle | `get_server()` |
| Длинный POST `a_check` | VKBottle | таймаут `wait + 10` секунд |
| Обновление `ts` | VKBottle | после каждого ответа |
| Обработка `failed` 1–4 | VKBottle | см. раздел 6 |
| Повтор при сетевой ошибке | VKBottle | задержка 0.1…6 секунд |
| Сохранение `ts` на диск | VKBottle | только при `skip_old_events=False` |
| Маршрутизация события в обработчик | VKBottle | `Router` |
| Идемпотентность обработчиков | **Приложение** | ответственность проекта |
| Дедупликация событий | **Приложение** | в MVP не реализуется |

`[ФАКТ]` В `run_polling()` каждое событие обрабатывается отдельной задачей
(`asyncio.create_task`). Это значит, что два события одного пользователя могут обрабатываться
параллельно; обработчики не должны рассчитывать на строгий порядок.

## 4. Настройки сообщества

`[ФАКТ]` Для работы нужен бот сообщества и включённый LongPoll. Точные названия пунктов
интерфейса могут отличаться; перед запуском их нужно сверить с текущим интерфейсом ВКонтакте.

Чек-лист:

- [ ] В сообществе включены сообщения (бот должен иметь возможность отвечать).
- [ ] В разделе «Управление сообществом → Работа с API» создан ключ доступа.
- [ ] В настройках LongPoll API включён сам LongPoll.
- [ ] Отмечено событие **«Входящие сообщения»** (`message_new`).
- [ ] Выбрана версия API. Ориентир — 5.199: `vkbottle==4.11.0` зависит от
      `vkbottle-types>=5.199.99.22,<6`.
- [ ] Callback URL, секрет и код подтверждения **не** настраиваются.
- [ ] Бот добавлен в сообщество и имеет право отвечать от его имени.

`[ПРЕДПОЛОЖЕНИЕ]` Для MVP достаточно только входящих сообщений. Событие `message_reply`
(исходящие сообщения сообщества) не включается: автоматическое определение ответа менеджера
не входит в MVP.

### Права токена

`[ФАКТ]` Токен сообщества ограничен по методам по сравнению с пользовательским токеном.

`[РЕШЕНИЕ]` Нужны минимально необходимые права:

- работа с сообщениями сообщества (`messages.send`, чтение входящих);
- доступ к информации о сообществе (`groups.getById`, `groups.getLongPollServer`).

`[ПРЕДПОЛОЖЕНИЕ]` В интерфейсе это соответствует правам «Сообщения сообщества» и
«Управление сообществом». Точные названия галочек нужно проверить при выпуске токена.

## 5. События

`[ФАКТ]` В документации сообщества описаны типы событий:

| Событие | Смысл | Используется в MVP |
|---|---|---|
| `message_new` | новое входящее сообщение пользователя | да |
| `message_reply` | новое исходящее сообщение сообщества | нет |
| `message_event` | нажатие callback-кнопки | нет |

`[ПРЕДПОЛОЖЕНИЕ]` Нажатие **текстовой** кнопки с payload приходит как `message_new`
с заполненным полем `payload`. Callback-кнопки потребовали бы `message_event`; мы их
не используем.

`[РЕШЕНИЕ]` Проверить это на тестовом сообществе до реализации всей навигации. Если payload
не приходит, пересмотреть механизм навигации (вариант — callback-кнопки и `message_event`),
но это меняет архитектуру и должно быть согласовано.

## 6. Сбои LongPoll и повторные попытки

`[ФАКТ]` Коды `failed` обрабатываются библиотекой:

| Код | Значение | Действие VKBottle |
|---|---|---|
| 1 | история событий устарела | берёт `ts` из ответа |
| 2 | ключ устарел | запрашивает новый сервер, сохраняет текущий `ts` |
| 3 | информация потеряна | запрашивает новый сервер и новый `ts` |
| 4 | неверная версия LongPoll | сбрасывает версию на 3 и перезапрашивает сервер |

`[ФАКТ]` При `ClientConnectionError`, `asyncio.TimeoutError` и `VKAPIError[10]` цикл
повторяет запрос с нарастающей задержкой `0.1 * n` секунд, максимум около 6 секунд.
При прочих исключениях вызывает `error_handler` и также делает паузу.

`[РЕШЕНИЕ]` Дополнительный «внешний» watchdog в MVP не нужен. Если процесс упал, его должен
поднять супервизор (systemd, Windows-служба или аналог).

## 7. Перезапуск и потеря событий

`[РЕШЕНИЕ]` Используем `skip_old_events=False`.

Плюс: после остановки процесс восстанавливает `ts` и получает события, накопившиеся за время
простоя.

Минусы и ограничения:

- `ts` сохраняется после передачи события в обработку, но **до** завершения обработчика.
  Падение в середине обработки может привести к потере события;
- повторный запуск после аварийного завершения может привести к повторной обработке
  последнего события;
- файл `.vkbottle/bot-polling/{group_id}.json` нельзя коммитить.

`[РЕШЕНИЕ]` Считаем повторную обработку допустимой: все экраны идемпотентны, повторная отправка
меню или карточки не создаёт побочных эффектов. Потерю события при падении посередине
принимаем как риск MVP; критичных операций (оплата, запись) в боте нет.

## 8. Чем LongPoll отличается от Callback

| Параметр | LongPoll | Callback |
|---|---|---|
| Инициатор соединения | бот опрашивает VK | VK вызывает сервер бота |
| Публичный URL | не нужен | обязателен HTTPS |
| Код подтверждения | не нужен | обязателен |
| Секретный ключ | не нужен | обязателен |
| Веб-сервер | не нужен | нужен |
| Задержка | до `wait` секунд | зависит от сети и сервера |
| Настройка | включить LongPoll и события | создать сервер, подтвердить, указать события |
| Подходит для MVP | да | нет, избыточен |

`[ФАКТ]` Требования Callback (URL, подтверждение, секрет) **не переносятся** на LongPoll.
Их наличие в настройках сообщества не требуется.

## 9. Ограничения и риски

1. **Один потребитель.** `[ПРЕДПОЛОЖЕНИЕ]` Несколько одновременно запущенных экземпляров могут
   конкурировать за одни и те же события. В MVP запускаем ровно один процесс.
2. **Нет гарантии доставки.** LongPoll не является очередью; при падении события могут
   потеряться. Критичных действий в боте нет.
3. **Параллельная обработка.** События обрабатываются задачами; общий изменяемый state
   (файл тихого режима) требует блокировки или атомарной записи.
4. **`ts`-файл.** Хранится в рабочей директории; при запуске из другой директории состояние
   не найдётся. Рабочая директория должна быть фиксированной.
5. **Версия API.** Устаревшая версия может не отдавать часть полей; версию фиксируем в конфиге
   и проверяем при запуске.
6. **Архивная документация.** Живые страницы `dev.vk.com` были недоступны 10.11.2026;
   настройки нужно сверить с интерфейсом перед запуском.

## 10. Проверка перед реализацией

- [ ] В сообществе включён LongPoll, отмечены входящие сообщения.
- [ ] Токен сообщества работает с `groups.getLongPollServer`.
- [ ] `message_new` приходит при обычном тексте и при нажатии текстовой кнопки.
- [ ] Payload приходит в поле `payload` строкой JSON.
- [ ] После остановки и запуска события не теряются (в пределах описанного риска).
- [ ] В логах нет токена и ключа LongPoll.
- [ ] Процесс поднимается супервизором после падения.
